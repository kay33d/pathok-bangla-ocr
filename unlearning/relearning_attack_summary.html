Does Forgetting Survive an Attacker With Five Words?

The five-shot relearning attack, extended from 3 arms to all 7 non-degenerate unlearning methods, plus a new control: the same attack run against 20 writers the model never saw at any training stage. If forget-writers recover no faster than genuinely unseen ones, unlearning worked. They don't.

Read the two FAILs carefully. Retain accuracy is rock-stable on all four arms — neither FAIL is a retain collapse. Amnesiac and DELETE fail because they already left substantial forget-signal in place before the attack even started (55.1% and 42.6%, matching their elevated wAcc-forget in the main comparison table), so there's simply less headroom left to climb past the fixed +50-point bar. Their final forget-accuracy (88.4%, 86.9%) lands in the same range as WIC's and Random Labeling's — this is "already leaky," not "attack-resistant."

Task BUnseen-Writer Control

Same five-shot, 150-step attack, run again against support words drawn from 20 writers the model never encountered at any training stage (sampled from the 31-writer test split). If a method truly deleted writer identity, its forget-writer curve should relearn no faster than this control. All ten arms shown; forget accuracy and unseen-control accuracy are the model's own restricted-head readout after 150 steps.

forget writers unseen-control writers
Oracle is the one genuine surprise. Its gap is strongly negative (−43.7): a model retrained from scratch without the forget writers relearns them slower than it relearns genuinely unseen writers — despite having equally never seen either group. Retain accuracy stayed pinned at 100% throughout, so this isn't a validity failure. It suggests the 20 forget-writer identities are intrinsically harder to separate from each other (or from retain writers) than a random sample of unseen test writers is — a property of the writer split, not evidence the oracle leaks information. Read oracle's negative gap as the opposite of every other row, not as noise to discard.
Fisher Forgetting is degenerate here too. Both forget (0.0%) and unseen-control (4.6%) sit at chance — the shock step already destroyed the writer head entirely, so there's nothing left for a 5-shot attack to relearn. Its small negative gap is a floor effect, not a finding.

Reading Both Results Together

Task A and Task B measure different things and agree. Task A asks "does retain accuracy survive a relearning attack" (yes, for all four arms). Task B asks "is what recovers actually forget-specific information, or just five-shot writer-ID being an easy task in general" — and the answer is forget-specific: every non-degenerate arm's forget-writers relearn 15–23 points faster than writers the model genuinely never saw. Combined, these are the same conclusion the frozen-encoder probe already reached, now from a completely independent instrument: output-level unlearning suppresses the writer head's willingness to answer, not the underlying information.
